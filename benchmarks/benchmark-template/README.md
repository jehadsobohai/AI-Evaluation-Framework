# Benchmark Template

This directory provides the official benchmark template for the **AI Evaluation Framework**.

The template defines a standardized structure for creating reproducible, transparent, and evidence-based AI evaluation benchmarks.

All benchmark packages developed using the framework should follow this structure to ensure consistency across evaluation projects.

## Template Contents

The benchmark template consists of the following components:

| File | Purpose |
|------|---------|
| `README.md` | Benchmark documentation |
| `metadata.yml` | Benchmark metadata |
| `prompt.md` | Evaluation prompt or task |
| `responses.md` | Model responses |
| `evaluation.md` | Evaluation report |
| `assets/` | Supporting benchmark resources |
| `results/` | Evaluation outputs and metrics |

---

## Benchmark Structure

Every benchmark developed using the AI Evaluation Framework should follow the standard directory structure below.

```text
benchmark-name/
│
├── README.md
├── metadata.yml
├── prompt.md
├── responses.md
├── evaluation.md
├── assets/
│   └── Supporting files
└── results/
    └── Evaluation outputs
```

This structure promotes consistency, transparency, reproducibility, and ease of reuse across benchmark implementations.

## Directory Contents

### README.md

Provides an overview of the benchmark, including its objective, scope, evaluation task, supported models, and usage instructions.

---

### metadata.yml

Contains machine-readable benchmark metadata, such as:

- Benchmark ID
- Title
- Version
- Domain
- Task
- Languages
- Evaluation Method
- Metrics
- Status

---

### prompt.md

Defines the benchmark prompt or evaluation task exactly as it should be presented to the evaluated AI system.

---

### responses.md

Stores the responses generated by the evaluated models.

Responses should preserve their original content without modification to support reproducibility and independent verification.

---

### evaluation.md

Documents the benchmark evaluation, including:

- Evaluation methodology
- Evaluation criteria
- Scoring
- Evidence
- Comparative analysis
- Findings
- Limitations
- Conclusions

Evaluation reports should follow the **Evaluation Project Standard (EPS)**.

---

### assets/

Contains supporting benchmark materials, such as:

- Source datasets
- Reference outputs
- Images
- Audio
- Documents
- Configuration files

---

### results/

Contains evaluation outputs generated during benchmark execution, such as:

- Metric scores
- COMET outputs
- Logs
- Summary tables
- Visualizations
- Processed evaluation artifacts

## Benchmark Development Principles

Benchmarks should be:

- Standardized
- Transparent
- Reproducible
- Evidence-based
- Well documented
- Easy to extend
- Independent of specific AI models whenever possible

---

## Best Practices

When developing a benchmark:

- Clearly define the evaluation objective.
- Use representative evaluation data.
- Document benchmark assumptions.
- Preserve original model outputs.
- Record evaluation settings.
- Document scoring methodology.
- Report benchmark limitations.
- Support reproducibility through complete documentation.
